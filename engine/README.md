# Market engine

A spec-first rebuild of the 42.space market creation pipeline. It lives next
to the legacy app (`../src`) while it is built and is meant to move into its
own repository once it replaces the legacy pipeline (see [Extracting](#extracting)).

## Why

The legacy pipeline drafts prose, extracts claims from it, revises the prose,
and has a model rebuild the market JSON at the end. Reviews apply to one
version, and a different version ships. This engine inverts that:

1. A typed **`MarketSpec`** is the only source of truth.
2. **Deterministic checks** prove what can be proven (outcome partition,
   timing order, edge-case termination, source structure) and return
   **findings** with a spec path and a concrete **counterexample**
   ("at exactly 100000 USD both Yes and No win").
3. Code-based **acceptance** decides, not a vote. Models and people supply
   **attestations** for what code cannot decide, bound to the spec's digest.
4. The market JSON is **rendered** from the frozen spec. `freeze` refuses
   any spec whose digest differs from the one that was accepted.

## Invariants

- The artifact delivered to the creator is the one that passed review:
  `freeze(spec, decision)` throws if the spec changed after the decision.
- `unknown`, `unavailable`, and `not_run` never count as a pass.
- A failed deterministic check cannot be overridden by any number of
  passing attestations.
- Findings and attestations are bound to a spec version (and attestations
  to a digest). An open finding from an older version keeps the decision
  `incomplete` until it is re-checked against the current version.
- Every rule `resolve()` applies (observation window, which observation
  settles, source precedence, the data deadline and outage fallback) appears
  in the rendered text, so changing any of them changes the artifact.
- Only `shortDescription` is non-authoritative. Every settlement field is
  rendered from structure and never rewritten by a model.

## Layout

| Path | What it does |
|---|---|
| `src/spec.ts` | `MarketSpec` schema: outcomes with stable ids, timing, sources with precedence, typed predicate (`numeric_threshold`, `categorical`, `freeform`), and edge cases that resolve to outcome ids |
| `src/checks/` | Deterministic checks. `runChecks(input)` validates the schema and runs all of them |
| `src/findings.ts` | `Finding`, `CheckResult`, `Attestation`: the contract between checks, agents, and acceptance |
| `src/acceptance.ts` | `decide()`: the acceptance policy |
| `src/render.ts` | `freeze()` and `renderMarketJson()`: the legacy final-market JSON shape, generated from the spec |
| `src/resolve.ts` | `resolve(spec, observations, now)` for numeric and categorical markets. Before `timing.dataDeadlineUTC` only the primary source can settle; after it, fallback sources and then the `source_unavailable` edge case apply |
| `src/rubric.ts` | The legacy rigor rubric, mapped to the checks and judgments that now enforce each item |
| `fixtures/` | 21 spec-level scenarios; 11 port a legacy `../eval/fixtures` scenario (named in `portedFrom`), the rest are new. Generated by `scripts/make-fixtures.py` |

## How the legacy rubric maps over

| Rubric item | Decided by code | Still needs a reviewer |
|---|---|---|
| `mece` | `outcomes.identity`, `predicate.partition` (numeric and categorical) | Freeform predicates (`predicate.partition` stays `unknown`) |
| `objective_source` | `sources.resolvable` (gating, precedence, extraction) | `judgment.objective_source`: is the source objective and does its content support the market |
| `timing_unambiguous` | `timing.order`, `timing.early_resolution` | — |
| `manipulation_resistant` | — | `judgment.manipulation_resistant` |
| `atomic_claims` | Typed predicate is atomic by construction | `judgment.atomic_claims` for the win-condition prose |
| `edge_cases_covered` | `edge_cases.terminate` | — |

Legacy fixtures about live retrieval (`rag-trap/dead-url`, `typo-url`,
`mixed-sources`, `multiple-dead`) are not ported: they need the source
investigator, which reads real content instead of probing reachability.

## Usage

There is no build step yet; import the TypeScript source directly (vitest,
tsx, or Node's type stripping all load it).

```ts
import { runChecks, decide, freeze } from './engine/src/index.js';

const { spec, results } = runChecks(input);          // schema + deterministic checks
if (spec) {
  const decision = decide({ spec, results, attestations, findings });
  if (decision.decision === 'accept') {
    const { market, specDigest } = freeze(spec, decision);
  }
}
```

## Development

```sh
cd engine
npm ci
npm run check   # typecheck + tests
```

`.npmrc` sets `legacy-peer-deps`: npm 10.9 crashes resolving vitest 4's
optional peers from scratch, and `vite` is listed explicitly instead.

## Not built yet

In rough order:

1. **Specification author**: creator intent → initial `MarketSpec`, and
   findings → proposed spec patches. One component commits patches and bumps
   `specVersion`; everything else proposes.
2. **Source investigator**: fetches source content server-side, records
   extraction examples and provenance, and attests `judgment.objective_source`
   or raises findings.
3. **Settlement challenger**: tries to break a spec and must return a
   counterexample; attests `predicate.partition` for freeform markets.
4. **Workflow**: one durable server-side run (persisted spec versions,
   findings, attestations, decisions) that the web app, CLI, and review API
   all call.
5. **Evaluation**: 30–50 real 42.space markets that were disputed, resolved
   ambiguously, or corrected by hand, with expert labels. The engine replaces
   the legacy pipeline only when it beats it on that set at a matched budget,
   measured on unsafe acceptance, unnecessary rejection, and correction effort.

## Extracting

To move the engine into its own repository with its history:

```sh
git subtree split --prefix=engine -b engine-only
# then push engine-only to the new repository's main branch
```
